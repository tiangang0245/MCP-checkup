# MCP 威胁模型（工具视角摘要）

> 摘自作者 2026-10-11 的调研笔记，只保留与本工具相关的部分。
> 标注 **待核实** 的条目引用前须回源验证，不作为已确证事实使用。

## 六类攻击面（按发生顺序）

| # | 攻击面 | 典型手法 | 代表事件 |
|---|---|---|---|
| ① | 供应链 / 注册表 | 恶意包上架、合法包被夺号更新、仿冒名（typosquat） | Deadbugz 投毒（2026-09，74 分钟渗透 23 个项目） |
| ② | 工具定义层（语义） | Tool Poisoning：描述里藏指令；Rug-Pull：过审后偷改定义 | Invariant Labs 2024-11 首发研究（**待核实**） |
| ③ | 工具执行层（RCE） | 参数未校验→命令注入；动态 eval / 反射；沙箱逃逸 | 2026"最严重 MCP RCE"（无 CVE 号，**待核实**）；Cursor 一键 RCE（CVE-2025-54795，**待核实**） |
| ④ | 协议层 | 会话固定、DCR 滥用、state handle 当凭据、SSRF 打内网 | Azure MCP Server 令牌被诱导外带 |
| ⑤ | 提示 / 上下文层 | 工具返回值携带注入指令（间接提示注入）、confused deputy | echoleak：WhatsApp MCP 0-click 外带（CVE-2025-32596，**待核实**） |
| ⑥ | 管理面 | Inspector / 测试 harness 默认 `0.0.0.0` 无鉴权 | 多篇文章列为"第一周必修" |

## 防护覆盖度对照

| 攻击面 | 协议层 | 网关 | 扫描器 | 工程实践 | 结论 |
|---|---|---|---|---|---|
| ① 供应链 | ✗ | 弱 | 中 | 弱 | 靠人审 |
| ② 工具定义语义 | 弱 | ✗ | 中 | 中 | 刚起步 |
| ③ 执行层 RCE | ✗ | — | **已证伪（漏检）** | 中 | 最危险 × 最薄弱 |
| ④ 协议层 | **强（MUST）** | 中 | 弱 | 强 | 规范红利已兑现 |
| ⑤ 提示注入 | ✗ | 弱 | ✗ | 弱 | 全行业空白 |
| ⑥ 管理面 | ✗ | 中 | 弱 | 强 | 靠运维纪律 |

协议层要点（2026-07-28 版规范）：令牌显式签发、每请求独立鉴权、代理客户端需显式同意、**state handle 不得当凭据**；DCR 退役改 CIMD + PKCE；改无状态设计；工具定义强制 JSON Schema 2020-12 校验。**但规范管不了存量服务器与客户端实现。**

## 本工具瞄准哪几格

| 攻击面 | v0.x | 做法 |
|---|---|---|
| ① 供应链 | v0.2 | 仿冒名编辑距离、远程 vs 本地 stdio 标注 |
| ② 工具定义语义 | v0.2 | 配置内 description / 字符串字段的指令注入模式（中·英）、零宽字符、异常长 base64 |
| ⑥ 管理面 | v0.2 | `0.0.0.0` / 无鉴权 / 明文密钥键名 |
| ② rug-pull | v0.4 | 工具定义 JCS 哈希固化 + 快照 diff（区分"外观改动 vs 实质改动"） |
| ③ 执行层 | v0.5 | 本地靶场 + 动态执行模式探测（eval / exec / 反射） |

## 已知空白（也是本项目的立项理由）

1. **动态行为检测**：静态规则追不了运行时路径，工具位空着。
2. **中文生态扫描规则**：国内注册表 / skill 市场没有中文语料的投毒规则。
3. **记忆 / RAG 投毒检测**：工具返回值污染 Agent 长期记忆，学术刚开头、工业几乎零。
4. **个人侧防护工具**：现有方案全是企业网关视角，用户量最大的一端没人做。← 本项目从这里切入。
